01 / INTENT

モデルを評価したい人の順番に合わせる

主な利用者は、変換済みモデルの動作を自分の端末で試し、用途・結果・制約を確かめたい開発者を想定する。現在の機能別ナビゲーションでは、試したいモデルに到達するまでに機能の選択やモデルの再選択が必要になる。

成功の状態
初めて開いた人が「試せるモデル」「その用途」「この端末での利用可否」を把握し、モデル別に並ぶデモを直接タップして、その説明と操作画面へ進める。提供側はモデルやデモの公開範囲を一か所の定義で調整できる。

今回設計するのは、モデル一覧、モデルを引き継ぐ起動、共通デモとの接続、公開・対応条件、既存データを守る移行である。モデル変換、推論アルゴリズム、性能改善、全モデルのiOS対応、新しい配布サーバー、モデル比較ベンチマークは今回の範囲に含めない。

本書は設計の正本。実装の状態は下記の移行方針と各Issue／PRで追跡し、HTML承認・コードの検証・実機確認・公開を区別する。

Modelsの構成

iOSの画面タイトルは英語のModelsとする。「モデルから、試したいデモを選ぶ。」の直下に「ダウンロード前でも、デモの解説を読めます。」を置き、一覧末尾には重複表示しない。モデル名をセクションタイトルにし、分類とダウンロード容量を補助情報として添える。右側の取得操作・状態は可視テキストを付けず、未取得はダウンロード、取得中は進捗リングと取消、取得済みはチェックと削除、失敗時は再試行のアイコンで示す。状態表示のチェックと操作ボタンを区別し、読み上げ名・操作名・進捗値を付ける。

モデル名の下の表記は英語の用途名 · 構造（確認済みの場合のみ） · 容量に統一する。用途はLLM、ASR、TTS、Information Extraction、Multimodal Embeddingなど、アプリが提供する変換成果物の能力を表す。MoEは用途と混ぜず、構造の情報として扱う（表記例：LLM · MoE · 16 GB。数値は書式例）。元モデルが対応していても変換成果物で扱えない用途は付けない。構造が未確認ならその項目を省略し、MoEでないことを推定してDenseと記載しない。用途・構造・容量は別のデータとして管理し、一覧とモデル情報は同じ整形処理を使う。検索は日本語の用途説明と英語の分類名の両方に対応する。

各デモは共通の「正方形アイコン＋名称」コンポーネントで表示し、名称は「比較デモ」「抽出デモ」など「○○デモ」に揃える。モデルとデモの対応表から生成し、同じデモは別モデルでも同じアイコンと名称を使う。通常は3列程度で縦に折り返し、幅・文字サイズに応じて列数を変える。10件でも固定数のタブ、横スクロール、途中のデモ選択画面を追加しない。検索はモデル名とデモ名の両方を対象とし、デモ名で一致した場合もモデルの所属を残して表示する。

アプリ・端末で対応確認済みの公開対象だけを掲載し、表示範囲の切替と任意ファイルの登録は設けない。未ダウンロードのデモアイコンも有効で、説明画面へ直接遷移する。モデル見出しからの取得では一覧に留まり、デモ説明画面からの取得ではそのデモ画面に留まる。どちらも完了だけでは推論を開始しない。

検索とナビゲーション

iPhoneのModelsでは、検索をコンテンツ内から下部ツールバーへ移す。標準のsearchableを使い、必要な場合はDefaultToolbarItemのsearchをbottomBarへ配置する。検索対象はモデルとデモで、入力に合わせて一覧を絞り込む。検索語のクリアと検索終了のキャンセルを用意し、0件なら検索語を含む結果なし表示を出す。検索だけのタブや中間画面は追加しない。

検索欄はModelsだけに表示する。iPhone縦画面では下部を基本とし、横向き・iPadの配置やキーボード表示時の移動は標準コンポーネントの適応に従う。戻る操作では一覧の検索語・スクロール位置を保持する。検索のキャンセルは検索語を消して全件に戻し、検索開始前の位置へ戻す。

Modelsとデモの大きなタイトルは、スクロール後も上部の標準タイトルで現在地を示す。iOSの上部バーにアプリ名を重複表示しない。macOSはウインドウをModelsとして識別し、サイドバーを絞り込む検索はその上部に置く。

デモ画面の構成

iOSはモデル名をタイトル、選んだデモ名をその下の見出しとして表示する。短い用途説明と、初期状態で閉じた「このデモについて」による詳細解説を置く。説明には試すこと・使い方・結果の見方を含める。固定個数のデモ切替タブは置かず、別のデモはModelsへ戻って選ぶ。

未取得時も説明の開閉、画面のスクロール、戻る、モデル情報、ダウンロード関連の操作は使える。入力・例文の適用・ファイル選択・推論・カメラ・録音・再生・出力保存など、デモ機能の操作領域は共通ホストで無効化する。見た目を薄くするだけでなく、操作自体を受け付けない。モデルを取得すると利用できる旨を説明の直下に表示する。

取得・検査が完了したら、その画面で操作領域を有効にする。勝手な入力送信・推論・撮影・再生は開始しない。解説の開閉、取得状態の更新で入力・結果・選択モデル／デモを消さない。既存の結果は表示用データとして保持できるが、未取得時の再実行や保存などの操作は無効にする。

04 / BEHAVIOR

選択は一度。準備と実行は区別する

状況・操作期待する振る舞い
通常起動モデル一覧を表示。前回モデルの読み込み・会話復元・カメラ起動・音声再生を自動開始しない。
デモを選択iOSはModelsのアイコンから指定のモデル・デモを引き継いで直接開く。未取得なら解説と無効化した操作領域を表示する。macOSはモデル選択で代表デモへ進む。入力送信・撮影・生成は利用者の明示操作で始める。
未取得モデルをダウンロードiOSはモデル見出しのアイコン、または未取得デモの案内から取得する。同じ成果物の状態はモデルに紐づく全デモで共有する。重複取得を開始しない。取得・検査完了後も現在の画面に留まり、デモ操作を有効にする。macOSは従来の準備画面案を維持する。
複数の変換版がある同じモデルの下にまとめ、現在の変換版を表示。端末向けの既定版を使う。利用者が別版を明示選択した場合は黙って置き換えない。
未対応・未検証iOSはアプリ・端末で対応を確認した公開対象だけを表示し、未対応・未検証モデルを載せない。公開モデル全体へ切り替えるUIは設けない。macOSの別環境向けモデルの紹介方法は引き続き検討対象。両OSとも起動時の条件検査は維持する。
準備の取消・失敗取消はエラー扱いにしない。iOSの取消は未取得状態に戻し、現在の一覧／デモ画面を保持する。失敗は見出しの再試行アイコンと読み上げ名、デモ画面では理由と再試行操作で示す。macOSは準備画面で再試行／別フォルダ選択を表示する。対象モデル・デモを保持し、未完了ファイルを実行可能として扱わない。
モデルが0件iOSは利用できるモデルがない旨を表示し、検索結果が0件なら検索をクリアできる。未対応モデルの掲載やローカル登録で補わない。macOSは対応モデルがない旨とローカル登録を表示する。空のデモへ飛ばさない。
ローカルモデル登録iOSは提供しない。macOSではモデル種別と成果物の契約を検査し「ローカル」に登録する。表示名だけで既知モデルや対応デモに結びつけない。不明な形式は理由を示して拒否する。

デモの入力例・結果・用途別診断は既存仕様を引き継ぐ。表示言語の変更でモデルの入力やセッションを作り直さない。モデル情報には配布元、変換版、量子化、対応環境、確認済み条件、検証記録へのリンクを置き、未計測の数値を補わない。

05 / CATALOG

公開する単位を、モデルとデモに揃える

次の4つは概念上の責務。Swiftの型名や保存形式をここで固定するものではない。

単位管理する情報
モデル安定したID、名称、用途、表示説明、公開範囲、変換成果物一覧。サイズや派生モデルの異なるものを同名だからと統合しない。
変換成果物成果物ID、revision・契約版、量子化／精度、配布元、容量、プラットフォーム、検証根拠、公開範囲。取得済みかどうかは別の端末内状態。
デモ定義デモID、用途別UI、必要な入力・実行機能。モデル名を埋め込まず再利用する。
モデルとデモの対応対応する成果物とデモ、公開範囲、端末条件、macOS等の入口に必要な代表デモ指定、補助モデル／OS機能の依存。能力名の一致だけで対応済みにしない。

公開範囲と利用可否を別々に判定する

公開範囲は「公開対象」「開発用」「非掲載」を提案する。通常配布用カタログには公開対象だけを含め、開発用項目は開発用の構成で追加する。公開可否の変更はカタログを変更したビルドで反映し、初版では遠隔配信による切替を導入しない。

表示・起動の条件
モデル、成果物、デモとの対応がすべて公開対象であり、端末条件・依存条件を満たすこと。起動直前にも同じ条件を検査する。画面だけ隠して、履歴や別の入口から起動できる状態にしない。

モデルの公開を外せば、その配下のデモ導線も外れる。特定デモだけ準備中なら対応だけを外し、モデルのほかのデモは残す。macOSなど代表デモを使う入口では、代表デモが外れたら代わりを明示する。iOSでは各デモを直接選択するため、代表デモの有無を表示条件にしない。どの入口も有効なデモが0件なら実行先を作らない。カタログ整合性の検査で見落としを防ぐ。

「非掲載」はアプリで紹介・起動しないという意味。既に配布した重みや公開ソースを非公開にするものではない。配布元のアクセス権とリポジトリで公開する情報は別に管理する。

06 / ARCHITECTURE

↓ 公開条件・端末条件・成果物の検査

起動コンテキスト → 用途別のAssembly → 既存デモUI / Store

↓ 既存のRunner / Service

用途別ランタイム → モデル・カメラ・音声などの資源

責務所有する状態・境界
カタログと条件判定静的な定義と純粋な利用可否判定。ファイル確認・OS情報の収集は実行部から入力する。
一覧・起動のStore選択モデル／成果物／デモ、準備状態、起動要求ID、画面遷移。デモ本文の入力・結果を一括所有しない。
モデル資源の管理取得・登録・検査・保存先・削除。既存ModelManagerの使える処理を再利用し、用途別バンドル検査を呼び分ける。
用途別Assembly検査済みの起動コンテキストから既存デモを組み立てる。デモ側の固定パス・前回選択が今回の選択を上書きしない。
既存デモのStore / Runtime入力・生成・結果・保存・停止・資源解放を担当する。共通の言語モデル実行器に、抽出や音声の契約を無理に統合しない。

起動コンテキストには、モデルID、成果物IDとrevision／契約識別子、デモID、検査済みのローカル資源参照、補助依存、起動要求IDを含める。UIはモデルの表示名やフォルダ名から接続先を推定しない。実際の形式は用途別の型で安全に渡す。

以下は全デモで守る共通契約を表す。具体的なSwift型と検証範囲は共通モデル契約とiOS共通UIに対応づける。

DemoDefinition

共通化するのは一覧、モデル表示、準備・失敗表示、遷移、同じ用途の画面。用途ごとの入力契約や評価方法は保持する。新しい非同期制御は既存のFeature / Store規約に沿わせ、Viewから取得・推論を直接呼ばない。

07 / LIFECYCLE

モデルの選択と、実行結果を混ぜない

  1. 別モデル／別デモへ移る要求を受けたら、現在の処理へ停止を要求する。停止中は重複した起動を受け付けない。
  2. モデル処理・カメラ・音声再生等の停止と、必要な保存・資源解放の完了を待つ。
  3. 新しい起動要求IDを持つコンテキストで次のデモを開始する。前の要求の遅れた結果は反映しない。

モデル一覧へ戻る場合も同じ終了経路を使う。入力・結果はデモとモデル成果物の組合せで区別する。初版では、同じアプリセッション内の入力・結果は元の組合せへ戻った際に復元する案とし、別モデルへは自動で引き継がない。デモを離れたらランタイム資源を解放する方針とする。

起動後の永続復元は既存機能の保存契約を保つ。チャット履歴を明示的に開いた場合は、その会話に記録されたモデルへ解決する。モデル不明・未取得・非掲載なら履歴本文は閲覧でき、再開は理由付きで停止する。新しいモデルへ履歴を黙って割り当てない。

移行で既存のモデルファイル、保存済み会話、生成物を削除しない。旧パス情報は契約を検査して取り込み、対応不明なら元の記録を残す。モデルの削除・登録解除はナビゲーションと別の明示操作とし、使用中の資源は削除しない。iOSの見出し右側の削除アイコンは確認を開き、対象モデルと解放する容量を示す。削除するのはモデル資源であり、デモの説明・入力・保存済み結果は残す。削除後は関係する全デモを閲覧のみへ更新し、再取得前の実行を拒否する。

同じモデル内でもデモ切替のたびに解放する案は、分かりやすい寿命管理を優先した初版の判断。再ロード費用は実測後に評価する。複数ウィンドウ間の資源共有方式は現状調査後に確定し、少なくとも他ウィンドウが使用中の資源を解放しない契約を守る。
