# iOS model library UI

`ModelLibraryUI` consumes `Store<ModelLibraryFeature>` and a `ModelDemoRendering` provider. It provides the model sections, shared demo tiles, system search, model status/actions, descriptions, and model information. The regular iOS app opens this view on ordinary launch through `PhoneModelLibraryScreen`.

The renderer has two distinct inputs. `preview(for:)` receives only a metadata selection and must create display-only content without model, camera, or audio resources. `content(for:)` receives the active validated session. The host calls it only when the library permits that session. Renderer content is embedded in the host's scrolling content and should not create a second vertically scrolling screen or another navigation stack. A modal sheet is separate from that embedded content: camera search shows its live camera, analysis metrics and similarity log in a sheet while it starts or searches, and the sheet may use its own navigation bar and scroll view. Swiping the sheet down or tapping its close button stops the search.

Acquisition controls, sizes, and failures use the selected variant's installation, and Model information shows a variant picker when the model has more than one visible variant or its selection is no longer visible. The demo host's navigation subtitle (`Variant: <title>`) and each Models row (`<classification> · <title> · <size>`) name the selected variant when the model has more than one visible variant or its only variant has a download definition; `ModelLibraryState.variantTitle(for:)` supplies that name and `rowDetail(for:locale:)` builds the row text. While a running demo switches variants, the subtitle keeps the running variant until the stop is acknowledged. A demo without a connected adapter keeps its description and shows that execution is not connected. The description host uses the same deletion confirmation as Models; after deletion it stays on the demo and keeps its description and inputs. When the runner finds that a running demo's model was deleted elsewhere, the demo stops and returns to its description with the download action, keeping its inputs and results.

The renderer must retain each demo's input/result state across view reconstruction. It must route operations through the execution gate and let the library runner handle stop-and-release acknowledgements. A disabled SwiftUI view is not the sole execution boundary.

The controller and real model runner are supplied by app integration; the iOS app uses `ModelLibraryRendering` and `ModelLibraryRunner` from `ModelLibraryRuntime` (see [Runtime](model-library-contracts.md#runtime)). Published model definitions require verified distribution metadata; this component supplies no invented repositories or model revisions. Individual demo redesigns remain separate from this shared host. Dynamic demo text currently resolves through the host app bundle; app integration must supply and verify the corresponding translations and searchable labels in both English and Japanese. The synthetic preview uses English demo names.

## Validation

The reusable UI compiles with the iOS 27 device SDK and through the independent [native preview](../Examples/ModelLibraryPreview/README.md) with the iOS 27 simulator SDK. Its String Catalog contains English source strings and complete Japanese translations. Compiled Japanese strings are present in the generated resource bundle.

The project generation manifest now retains the existing ObjectFinder dependencies, examples, and camera usage text that were present in the Xcode project but absent from `project.yml`. Regenerating the project must not remove those existing app capabilities.

An isolated iPhone 17 / iOS 27 simulator fixture confirmed navigation while stopping, a failed stop followed by retry, and return to Models after acknowledgement. The deletion alert was checked in English and Japanese for the model name, deletion explanation, and size. Acquisition buttons exposed 44 × 44 point accessibility frames and accepted a tap 20 points from their center after the explicit label hit-region update. These checks used synthetic resources, not real models.

The package test runs discovered 539 tests: 507 passed and 32 optional model/fixture-dependent tests were skipped. Strict lint and format checks passed. Both the main macOS Release and iPhoneOS Release builds passed; the latter used unsigned device SDK compilation. The main simulator build cannot link Core AI in the installed simulator SDK, so the standalone preview supplies the simulator UI checks.

Full navigation coverage, Dynamic Type, VoiceOver, and device behavior still require the manual checks listed in the preview. HTML approval and successful compilation do not complete these checks. The current functional-screen HTML proposals are linked from the design review index.

## Regular iOS launch

Build and run the **CoreAISamples-iOS** scheme without diagnostic arguments to open Models. `IOSDemoLaunch` selects the launch destination before constructing legacy demo stores. `IOSDemoCatalog` lists GLiNER2.5-multi (comparison, extraction, inspection), EmbeddingGemma 2 (image search, video search, camera search), and Irodori (speech). Search aliases include the app's English and Japanese labels without rebuilding the Store when the display language changes.

The catalog pins the published distributions (#210): GLiNER2.5-multi **FP32**, and EmbeddingGemma 2 **FP16** (the default) and **INT4/INT8 PTQ**. Irodori instead pins a local FP32 folder with 14 verified files (#335/#336), selected with **Import model**. Model rows show acquisition progress, cancellation, retry and deletion for the selected artifact. Since #192, `PhoneModelLibraryScreen` assembles the store through `IOSModelLibraryAssembly` with the managed store, the transfer service, and `ModelLibraryRunner` instead of `ModelLibraryBrowsingRunner`. A download requests only the files of the selected artifact's definition, anonymously over HTTPS, and promotes them after their sizes, SHA-256 and contract pass. Inspection can also make an artifact ready from a matching legacy folder in Documents, which is copied and never moved or changed. All seven demos have registered adapters (#193–#197, #129, #336); a demo session, and with it adapter content or work, starts only after its selected artifact is validated. Running the demos on an iPhone remains a user check. Irodori keeps text and seed across a closed session, while discarding audio, export tickets and result messages. `ModelLibraryBrowsingRunner` remains for hosts and tests that only browse; it refuses downloads.

Explicit `--image-search`, `--object-finder`, `--truck-inspection`, and `--legacy-demos` use the original demos. `--extract-eval` and `--image-search-eval` retain the evaluation routes, and `--model-library-selftest` writes the self-test report described below. Extract evaluation resolves relative gold/form/asset/output paths against Documents on iOS; macOS retains its current-directory behavior. These explicit diagnostic routes are separate from ordinary Models browsing.

`IOSDemoLaunchTests` covers destination precedence, including the self-test and its `--acquire` target, catalog ownership and the published definitions, translated search aliases, descriptor decoding, and refusal to execute through the browsing runner. Production iPhoneOS and macOS builds and CPU regression checks accompany the startup change. Physical-device UI acceptance remains a user check after merging.

An isolated iPhone 17 / iOS 27 simulator target compiled the actual `PhoneDemoApp`, `PhoneModelLibraryScreen`, `DemoLanguage`, app strings, and shared Feature/UI, with only diagnostic/legacy view types substituted. It verified ordinary Models startup, EN/JP switching, Japanese demo search, the description-only controls of the catalog before #210, and returning with the search query preserved. No model or physical-device operation was part of that check.

### Self-test

`--model-library-selftest <output.json>` checks the assembly without loading a model, writes a JSON report, and exits with status 0 when every check passes and 1 otherwise. The iPhone app resolves a relative path against Documents; the Mac app resolves it against the current directory. `--acquire <artifact ID|all>` (or `--acquire=<value>`) adds an acquisition through the ordinary path. For an uninstalled local Irodori artifact, use `--acquire irodori-v4.1-small-mf-fp32 --import-local-bundle <folder>`; the selected folder is copied and preserved. `all` requires local artifacts to be installed first. The app supplies its actual catalog, and catalog construction failures are written to the diagnostic report. The report records:

- that the app's catalog (`IOSDemoCatalog` on iPhone, `MacDemoCatalog` on the Mac) passed catalog validation (every link names a catalog demo, and every artifact has well-formed files and root), its demo IDs, and the number of models and demos visible for release on that platform;
- each artifact's contract, distribution (`repository@revision`), upstream revision, file count, and inspection result. local artifacts identify their source by manifest SHA instead of a distribution. An artifact without any valid source stays `missing`. Inspection verifies file content without specializing or executing a model;
- the managed root relative to the home directory, whether it exists, and whether it is excluded from backups;
- the registered demos with whether they match the catalog, together with the demos declared unconnected, and on iPhone the capability states. On the Mac only the OCR demo is registered and the other seven demos are unconnected; the Mac app does not read device permissions, so its report omits them and says so in `scope`;
- with `--acquire`, an `acquisition` section. The self-test creates a library store for the report's platform with `ModelLibraryAssembly.makeLibrary` (the app's assembly on iPhone, with its migration candidates; on the Mac, a store at the same root with no adapters or candidates), sends `refresh`, and then requests acquisition of each selected artifact that is not ready, one at a time, waiting until it is ready or has failed (at most 30 minutes each, after which the transfer is cancelled). For each artifact it records the distribution revision, the route (`installed` when it was ready before the run, `migration` when the refresh made it ready, `local-import` for a selected local folder, `download` for a remote source), the defined and the measured bytes, the seconds of its download, the library state, a new inspection of the managed store, the validated identity and the failure, plus the seconds of the refresh. Any artifact that is not ready, not inspected as ready, or whose measured bytes differ from its definition is a failure. The report contains no local absolute paths.

`ModelLibraryAssemblyTests` checks the report with the real catalog and fake adapters. `LocalSpeechCatalogTests` also checks the Irodori entry and reporting of catalog failures. The run on a device is part of the [integration record](validation/ios-models-integration-20261018.md).

## Mac sidebar

The Mac app acquires, checks and deletes models through the same Feature, store, runner, managed storage and transfer (#461). `MacModelLibrary` (`CoreAISamples/Demos/ModelManager/MacModelLibrary.swift`) gives each window a library store with its own owner on one `ModelLibraryAssembly` shared by all windows, at the same managed root as before (`Application Support/<bundle ID>/ModelLibrary`). The assembly registers only `OCRMacAdapter`. `MacDemoCatalog` lists Qwen3.8 27B, Clef-Flash 9B, EmbeddingGemma 2, GLiNER2.5-multi, Irodori and TeleOCR in the sidebar order, with the Mac demos under each model, and the seven demos other than OCR are declared unconnected when the catalog is validated against the registry. Unconnected means that a demo has no adapter and no session; the other demos use their downloaded models through usage leases instead. The shared artifacts (GLiNER2.5-multi FP32, EmbeddingGemma 2 FP16 and INT4/INT8 PTQ, and the Irodori reference voice download) come from the same definitions as iOS and differ only in their platforms; Qwen3.8 27B and Clef-Flash 9B use Mac-only download definitions pinned to the [published revisions](validation/mac-models-distribution-20261104.md), including all 12 and 25 files respectively.

Each model heading shows **Model information** (ⓘ) and `ModelAcquisitionControls` for the selected variant: download, progress with cancel, retry, or a check mark with delete. TeleOCR's local artifact imports the evaluated folder instead. A failure appears in a row under the heading. Deletion uses the shared confirmation and is unavailable while the OCR demo runs the same model or while a demo of the window holds a usage lease on it; **Clear Prepared Copy** is unavailable in the same cases. When a deletion is still refused because another window uses the model, the heading keeps the check mark and the row under it says to close that model's demo first. The popover shows `ModelInformationView`, where EmbeddingGemma 2 selects FP16 or INT4/INT8 PTQ while no demo of the window holds a usage lease on it, and, for an installed model, **Clear Prepared Copy**, which deletes the `AIModelCache` entries of every `.aimodel` in the artifact's files. The line at the top adds the size of the managed root to the size of the earlier download folder (`models/`, retained as a migration source) and shows the available space. It is measured when the sidebar appears and whenever an acquisition, import, deletion or check ends.

`ModelAcquisitionControls`, `LibraryFailureView`, `ModelDeletionRequest`, `modelDeletionAlert` and `ModelInformationView` are public and build for macOS; `ModelLibraryView` and `ModelDemoHost` remain iOS views, and the iOS model information sheet uses the same `ModelInformationView`. The Irodori screen uses the downloaded model through a usage lease (#462): `MacModelLibrary.use(.irodori)` when the screen appears and `stopUsing(.irodori)` when it disappears. Once the lease is granted, the screen opens the model's folder unless the same folder is already open, and without a download it shows one line that points to the heading in the sidebar. It has no folder choice. When the downloaded files go away, the speech screen forgets the model, its path and its audio (`bundleUnavailable`). After another window deletes the model, returning to the screen is refused and the library inspects the artifact again, so the heading returns to the download button and the screen shows the guidance line. **Generate speech** is available only while the screen's lease is granted for the folder that is open. If opening the folder fails, select another demo and return to try again. The product comparison and its extraction lab (GLiNER2.5-multi) and image and video search (EmbeddingGemma 2) use the downloaded model the same way (#463): the screen, and the lab's sheet, each take a lease while shown and return it when they disappear, open the leased folder unless it is already open, show the guidance line without a download, and have no folder choice. **Add a product**, indexing and searching are available only while the lease is granted for the folder the screen uses. When the downloaded files go away, the product comparison forgets its folder (`modelUnavailable`), the lab releases its model (`closed`, which now releases it in the standalone mode as well), and image and video search release theirs (`disappeared`); their inputs and results stay. `--gui-e2e … --extract <folder>` and `--embedding-bundle <folder>` keep using the given folder without the library or a lease. Qwen appears in the conversation model menu only after acquisition. Choosing it requests a usage lease, then loads its managed folder. The selection request belongs to the window, so leaving the conversation while the lease is pending does not strand the request. **Unload model** releases the native session and model while retaining the transcript for a later reload. Decide and Recipes open Clef from the library when shown and have no model folder chooser. Their execution buttons require the granted folder to match the loaded model. Their services keep a separate runtime lease until current work ends and both the model and its document context are released; this also protects files when a window closes. Closing and reopening waits for that release acknowledgement before loading again. Cancelling application termination reopens the still-visible demo after cleanup completes. The OCR demo still opens through its adapter and session. The separate Models screen, folder registry and legacy downloader have been removed. The GUI diagnostic uses the acquired Qwen artifact by default; an explicit `--model` keeps the direct diagnostic route.

## Recorded artifact inspection

Ordinary `.refresh` checks the installation ledger and the artifact's structure. An entry must match the model, artifact, contract, source kind, revision, upstream revision and total size. All expected files must exist as regular files at their recorded sizes; missing files, extra files/directories and symlinks are rejected. This path reads the ledger and file metadata without reading model or manifest contents.

A same-size content change is intentionally not detected by this lightweight check. Use `ManagedModelStore.inspect(..., verification: .full)` or the explicit `--model-library-selftest` diagnostic for complete SHA-256 and manifest verification. Orphaned artifacts and missing, corrupted or mismatched ledger entries still require complete verification before registration. The ledger format is unchanged. A full inspection reports content failures without removing the installation entry, so the installed files remain deletable. A later ordinary `ready` result describes the recorded identity and current structure, not a renewed content-integrity guarantee; callers requesting full verification must use that result.

Downloads are fully checked by promotion, imports retain streaming hashes and full promotion, and migration retains complete source and destination checks. An interrupted migration with a cleanup journal verifies the destination fully before removing the old or retired source. A bad destination remains unavailable and keeps both source and journal; a verified destination remains available if source cleanup alone fails. Such pending migrations can still take longer than an ordinary refresh. Refresh timing and UI controls are unchanged.
