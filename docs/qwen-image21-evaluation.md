# Qwen Image evaluation contracts

This implements evaluation contracts for [#215](https://github.com/oka-yuji/coreai-samples/issues/215), under QMI practical v2. Mobile feasibility and image quality remain unverified.

The source is `Qwen/Qwen-Image-2.1-Turbo@fc13ba1986fcb905854dc8de2f52eee395f49b5b`, Diffusers `b800f828f3951c4d206e154411bcbfa693cd322e`. Use the locked recipe environment. Model jobs require the shared heavy-job lock. CPU contract validation and tokenizer/image fixture preparation do not execute learned networks.

## Frozen inputs

[`evaluation-cases.json`](../Tools/Conversion/recipes/qwen_image21/evaluation-cases.json) defines 15 generation and 15 editing inputs, each with seeds 20261018 and 20261021. Japanese and English cover objects, people, text, background changes, preservation and alpha. Editing inputs are original deterministic drawings, including an illustrated person. This does not establish photographic identity preservation.

```sh
QI_PYTHON="$PWD/.local/conversion/qwen_image21/.venv/bin/python"
"$QI_PYTHON" -m Tools.Conversion.adapters.qwen_image21.fixtures \
  --definition Tools/Conversion/recipes/qwen_image21/evaluation-cases.json \
  --snapshot "$QI_SNAPSHOT" --output "$QI_FIXTURES"
"$QI_PYTHON" -m Tools.Conversion.adapters.qwen_image21.evaluate \
  inventory "$QI_FIXTURES" "$QI_FIXTURES/fixtures.json"
```

Use a new directory. The inventory contains prompt bytes, authored PNGs, processed tokens, source template removal, text/multimodal positions, masks, expanded image-slot layout, VAE input and saved noise. `text-preprocessing.npz` uses zero vision embeddings deliberately: it verifies placement and preprocessing, not learned encoder outputs. General EXIF, tagged-color and resize boundaries belong to #217's additional goldens.

Noise is saved Float32 `[1,1024,64]`, generated by PyTorch 2.9.0 CPU `randn`, spatially packed in the original order. Matching a seed in a different RNG is not equality. Raw file SHA is part of each input record.

Reference/candidate records must match fixture ID, source revision, prompt/reference/noise SHA, processed-token SHA, layout SHA, operation and saved sigmas. Same-size edits, symbolic links and unsafe relative paths are rejected. Failed and unreviewed cases remain in the suite.

## Profile format 2

[`profile.py`](../Tools/Conversion/adapters/qwen_image21/profile.py) defines exact physical boundaries. [`validate_profile`](../Tools/Conversion/adapters/qwen_image21/evaluation.py) is the executable JSON contract.

| Field | Contract |
| --- | --- |
| `source` | Exact source/implementation revisions, dependency-lock SHA, converter file SHAs |
| `workload` | 512-square output/reference, batch one, at most one reference, text capacity 512, joint capacity 2304; 1536 is generation-only |
| `components` | All five: vision, text, denoiser, VAE encoder, VAE decoder; one stateless `main`, relative asset path, exact input/output names, shapes, dtype and layout |
| `compute_dtype` | Float32, Float16 or BFloat16 per component; independent of capture and physical I/O dtype |
| `weight_encoding` | Actual representation; the dense baseline records Float32 |
| `scheduler_compute_dtype` | Float32 Euler accumulation |
| `scheduler_delta_dtype`, `scheduler_product_dtype` | Round the scalar delta and product in the model-output dtype before adding to the Float32 sample |
| `model_timestep_rule` | Float32 sigma × 1000, cast to latent dtype, then divide by 1000 in that dtype before the denoiser |
| `scheduler_output_dtype`, `cast_back` | Cast back to model-output dtype after **every** step |
| `rounding` | Nearest, ties to even |
| `denoiser_fp16_clip` | `[-65504,65504]`, applied by the original graph only on its FP16 path |
| `zero_centered_norm_dtype` | Float32 for source `weight + 1` normalization |
| `sigmas`, `terminal_sigma` | Saved eight sigmas, then zero; no implicit dynamic shift |
| `prefix_kv_cache` | `false`; unrelated to Core AI specialization caches |

`row-major` is the serialized host boundary, not an assumption about preferred NDArray strides. Native packing must honor actual descriptor strides. Indices remain Int32 and masks remain Bool when floating precision changes.

Native golden testing exposed a finer scheduler rule on 2026-10-21: the source upcasts `sample`, but `dt * model_output` still follows PyTorch's scalar promotion. On PyTorch 2.9 CPU, Float16/BFloat16 delta and product rounding must precede the Float32 addition and final cast-back. This matched 20,000 values at all eight steps for both precisions; keeping the delta/product entirely Float32 did not. The plan's Float32 accumulation remains, with this required intermediate rounding made explicit. MPS full-reference checks remain pending.

```sh
"$QI_PYTHON" -m Tools.Conversion.adapters.qwen_image21.evaluate baseline-profile \
  --bundle "$QI_FP32_BUNDLE" \
  --dependency-lock Tools/Conversion/recipes/qwen_image21/uv.lock \
  --output "$QI_PROFILE"
"$QI_PYTHON" -m Tools.Conversion.adapters.qwen_image21.evaluate profile "$QI_PROFILE"
```

The comparison profile hash uses canonical JSON SHA-256. Deployment identity instead hashes the **saved raw bytes** of `bundle.json`; that manifest is excluded from its internal asset inventory. #216 produces verified assets, and #263 pins the independently expected hash/inventory. A bundle's own `passed` field does not confer trust.

The version-two bundle envelope is `{"format":2,"profile":<profile v2>,"assets":{<relative path>:{"bytes":<Int64>,"sha256":<lowercase hex>}}}`. Every component has a distinct asset directory represented in the inventory; `bundle.json` is excluded. Total sizes must fit Int64. `validate_manifest` validates the logical envelope. Filesystem completeness, links, actual bytes/SHA and Core AI descriptors require the importing storage/runtime boundary; logical validation alone is not readiness.

## Independent references and gates

```sh
"$QI_PYTHON" -m Tools.Conversion.adapters.qwen_image21.suite_reference \
  --snapshot "$QI_SNAPSHOT" --fixtures "$QI_FIXTURES" \
  --precision fp32 --output "$QI_REFERENCE"
```

Run separately for `fp16` and `bf16` when evaluating them. The command uses the pinned original pipeline, records every output/latent SHA and repeats a generation and edit for repeatability. It owns the shared lock. `--run-ids` permits a limited diagnostic run; all other rows stay `not_run` and the suite stays incomplete. This trace run is not clean latency evidence.

The unreviewed quality table is published with the run summary, including before loading. A load, input, decode or repeat failure therefore preserves all 60 rows and their failed/unrun reference status instead of leaving no table after an exception.

An optional `--vae-precision fp32` loads VAE weights directly from the checkpoint at that precision. This uses an explicit boundary adapter: canonical image tensors enter the VAE at its dtype, original encode/normalization/packing runs, and condition latents return to the prompt/denoiser dtype. Decoding follows the original pipeline's VAE-dtype path. The identity records this route and all five component dtypes; it is distinct from an unmodified all-FP16 reference.

| Comparison | Purpose |
| --- | --- |
| A0 FP32 ↔ A1 FP16 | Precision loss |
| A0 FP32 ↔ A1 BF16 | Precision loss |
| A1 FP16 ↔ A1 BF16 | Direct precision difference if both are evaluated |
| A1 ↔ B with the same precision | Quantization loss |
| B ↔ C with identical quantized weights and input | Conversion error |

The existing FP32 gate remains normalized maximum error ≤ 0.001 and normalized RMSE ≤ 0.0001. Denominators are `max(max(abs(reference)), 1e-12)` and `max(rms(reference), 1e-12)`. Nonfinite output fails. The block probes retain their failed FP32-gate results for FP16/BF16.

The versioned [numeric policy](../Tools/Conversion/recipes/qwen_image21/numeric-gates-v1.json) was frozen on 2026-10-21 JST, after the block feasibility probes and the mixed-precision source suite, before full quantized-candidate evaluation. Its canonical SHA is `6e3c72b9321b6cdc105f8ddf38aaea9c151ab912e2bb9c36dd57654b31d4c793`.

| Component compute dtype | Normalized maximum | Normalized RMSE |
| --- | ---: | ---: |
| Float32 | 0.001 | 0.0001 |
| Float16 | 0.00390625 | 0.0009765625 |
| BFloat16 | 0.03125 | 0.0078125 |

The new low-precision limits are engineering budgets of four epsilon and one epsilon. These coefficients are a design choice, not theoretical rounding bounds, per-element ULP limits or thresholds established by the pilot results. The maximum-error denominator is the maximum absolute reference value over the selected tensor region. Outliers can dominate it, so local numeric checks and final quality checks remain separate.

The **final free-rollout limits are unchanged for every precision**: latent normalized RMSE ≤0.005 and decoder RGBA absolute RMSE ≤0.01. These reuse the existing output-difference budgets in `verify.py`. Both routes use the same initial noise and conditions but feed back their own preceding latent. RGBA means all four channels before clipping/compositing/byte conversion. Captures are Float32; error calculation remains Float64. A low-precision implementation can pass its component limits yet fail the final-output limits.

`numeric_metrics` records the policy and metric-code hashes for one comparison. Its local `passed` value is not suite/profile verification. #216 must compare each applicable component output, each of eight fixed-input denoiser steps, and both final outputs independently for every one of the 60 runs. The policy fixes valid regions so padded rows cannot dilute comparisons. Token/index/mask/shape/sigma equality remains exact. Generation does not use vision/VAE encoder and must record that reason; editing requires both.

Mixed profiles choose the budget per component: a Float32 VAE retains the Float32 limits. Same dtype alone does not establish matched weights, dequantization, normalization, clipping or scheduler behavior. Complete independent reference evidence and the separate quality gate remain required. Defining BFloat16 limits does not verify a BFloat16 profile whose source suite has not run.

Previously observed FP16/BF16/W4 block failures under the old FP32 gate are retained. New acceptance requires new full-suite runs; retrospective rescoring alone cannot accept a candidate. A later failed candidate must not automatically widen these limits. Any policy change needs a new version, rationale, impact and new confirmation runs, retaining old results.

Human ratings use 0 = failed, 1 = acceptable, 2 = good, null = unreviewed. Instruction, text, detail, preservation and alpha are separate applicable axes. The provisional target is ≥90% success on every applicable axis and at most two newly failing outputs among all 60. `quality_summary` preserves original failures and rejects missing rows/changed axes. Unreviewed ratings never pass; source limitations remain visible.

A newly failing output has at least one axis that was acceptable/good in the reference and failed in the candidate. An existing reference failure on another axis does not hide that regression. Multiple regressed axes in one output count once toward the two-output limit, and `new_failure_axes` records which axes regressed.

## Time and memory

The existing CLI accepts `--diagnostics off` or `trace`; default trace preserves earlier captures. Off writes final PNG and scalar metadata without intermediate tensor dumps. `measurement.seconds` begins before bundle hashing in the CLI and ends after the final image is saved. Legacy `seconds` retains its narrower function boundary. Preparation, loads, inference, individual DiT steps, release and saving use monotonic intervals.

The shared machine lock covers bundle hashing and input preparation as well as model execution. Metric reports replace the previous JSON atomically. If saving fails while an exception is already propagating, its note records the I/O failure without replacing the original exception. A full disk can still prevent the terminal snapshot: the last saved JSON and the process outcome must be interpreted together.

Loading and first execution can include specialization. No separate specialization timer is exposed: `specialization_seconds` remains null/unavailable and load is labeled `load-including-specialization`. Subtracting timings is not a measured specialization cost.

Point observations separate RSS, footprint, graphics footprint and process-lifetime kernel peak. The macOS host cannot read an iOS app budget or observe the Core AI delegate's MTLDevice allocation counter, so both remain null/unavailable. `NSProcessInfo.thermalState` records actual thermal state. These values are not summed into “RAM,” and before/after samples are not phase peaks.

`live_memory_peak` unions declared allocation lifetimes, including old/new component load overlap. `storage_id` identifies an allocation, not an asset hash. Aliases count their backing storage once; disjoint lifetimes are not added. Unknown workspace/cache/activation categories leave `planning_peak_bytes` null while preserving the known contribution.

Aggregation partitions by profile/workload hash, device, OS build, route, operation, cache state, diagnostics, power and thermal state. Cache states are `uncached-cold`, `cached-cold`, `warm`, `continuous`. A group needs 20 completed samples for the sample-count flag. Quantiles use nearest-rank p50/p95 plus maximum. Failures, cancellations and unrun cases retain null completed latency and their outcome counts.

The aggregate CLI input is an object with `runs` and optional `minimum_samples`, for example `{"runs":[...],"minimum_samples":20}`.

```sh
"$QI_PYTHON" -m Tools.Conversion.adapters.qwen_image21.evaluate aggregate runs.json
"$QI_PYTHON" -m Tools.Conversion.adapters.qwen_image21.evaluate memory allocations.json
"$QI_PYTHON" -m Tools.Conversion.adapters.qwen_image21.evaluate quality ratings.json
"$QI_PYTHON" -m unittest discover -s Tools/Conversion/tests -v
```

## Current evidence

The 30-input/60-run fixture inventory has been generated and verified. CPU tests cover input/profile changes, fixed boundaries, alias lifetimes, load overlap, failed/missing metrics and condition-separated aggregation.

The all-FP16 MPS reference completed 48 outputs, then failed on `e10-20261018` when the decoder returned nonfinite values. The remaining 11 rows remain `not_run`; this profile did not pass. A separate VAE probe reproduced nonfinite FP16 output from the saved final latent while FP32 decoded the same reconstructed input finitely. The explicit FP16-network/FP32-VAE route then completed diagnostic runs `e10-20261018` and `e11-20261018`.

The explicit FP16-network/FP32-VAE source suite subsequently completed all 60 runs and both required repeats. Every repeated latent step and RGBA tensor had zero observed difference. This establishes repeatability only for those two inputs and that MPS route. It does not prove image quality or cross-runtime error bounds.

The FP32 source suite also completed all 60 runs and both repeats with zero repeated latent/RGBA difference. [Recorded cohort evidence](research/qwen-image21-evaluation-20261021.json) preserves both identities and summary hashes. A0↔A1 comparisons rechecked every input pair and saved tensor hash. Final-latent normalized RMSE had median 0.001845 and maximum 0.247003; RGBA absolute RMSE had median 0.001620 and maximum 0.231370, both maxima at `g14-20261021`. These are descriptive precision differences, not conversion-gate or image-quality decisions.

The first Core AI diagnostic-off baseline attempt was stopped during denoising when available disk space fell to approximately 116 MiB. Report persistence also failed with ENOSPC; the last valid snapshot ends at VAE encoder release. After process exit, approximately 8.4 GiB was available. The disk-consumption breakdown was not captured. Trace mode did not run. Neither invocation produced a completed latency sample.

The saved failed/unrun rows reproduce the same aggregate through the CLI: zero completed samples and null p50/p95/maximum. Cache entries existing before launch do not prove a runtime cache hit or sufficient temporary space. A new off/on attempt needs a larger free-space margin and a live stop threshold, in new output directories.

QMM-04 remains incomplete. The reference cohorts, unreviewed 60-row quality tables and numeric policy are saved; they do not establish mobile quality or performance. The conversion CPU suite contains 172 tests: 159 passed and 13 optional tests for other models were skipped.

## Scope and review

The initial 350–550-line estimate did not cover the full five-component tensor contract, actual input-file bindings, failure/cancellation records and dtype-specific gates. A split between contracts/fixtures/aggregation and reference/measurement runners was considered. They share the same identities, failure states and acceptance criteria; retaining one reviewed evaluation unit avoids accepting a schema separately from the real source and CLI paths that exercise it. This remains #215's original scope and 5 SP estimate; the estimate is not rewritten from line count or elapsed model time.

Independent reviews covered contract, numerical, failure-state and lifecycle boundaries. Regression fixes include missing/changed quality axes, duplicate or shortened fixture sets, input-path/hash mismatches, failure tables, newly failed axes hidden by prior reference failures, preparation outside the machine lock and report I/O failures replacing a cancellation. No full quantized candidate or mobile route is accepted by this tooling-only result.
