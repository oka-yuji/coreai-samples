# Receipt Desk — Mac でレシートを分類して台帳へ

[English](receipt-desk.md) · [JEV モデルのガイド](jev27b.ja.md)

レシート画像や PDF を渡すと、Mac 内の Vision が文字を読み、Core AI 版 JEV-27B が費目を提案します。
店名・日付・合計・用途を確認してから、経費台帳と元レシートのコピーを保存するデモです。
金額を JEV に生成させず、計算には整数の円金額を使います。

## 試す手順

1. Models の **JEV-27B → レシートを分類して経費台帳へ** を選び、モデルを取得します。
   取得量は16,064,821,387 bytesです。検査が終わったら **Receipt Desk を開く** を押します。
2. **4 件のサンプルで試す**、または **レシートを追加して処理…** を押します。
   ファイルのドロップでも処理を始められます。アプリや空の画面を開いただけでは文字認識・推論を始めません。
3. 読取り・分類の進行に合わせて、一覧と費目別の件数が更新されます。
   中央の原本と読取り原文、右側の抽出項目・分類スコアを見比べます。
4. 必要なら項目や購入の用途を修正します。**もう一度提案** で JEV が再判定します。
   店名・用途の変更は古い費目候補を無効にし、どの項目でも値が変わると確認済みの状態を解除します。
   費目を手で選ぶこともできます。
5. **この内容で確定** を押します。必須項目が揃い、OCR の警告がないものは **確認可能なものを確定** でまとめて確認できます。
   合計に含めるのは確認済みだけです。混在購入のサンプルは「要確認」のままになります。
6. **書き出す…** で保存先の親フォルダを選びます。新しい `ReceiptDesk-<UUID>` フォルダに
   `ledger.csv`、`ledger.json`、年/月/費目別のレシートコピーを保存します。
   確認済みレシートの相対配置は右側にも表示します。保存先選択のキャンセルでは、確認した内容を保持します。

**停止** は実行中の処理の終了まで待ちます。停止と同時に読取りや書き出しが完了した場合も、その結果を保持します。
**未処理を再開** で続けられます。処理時間の表示は、そのレシートの実 OCR/JEV 呼出しを測った値です。
最初のモデル取得・準備とは分けていますが、JEV の呼出し中に必要になった実行部の再準備は含みます。性能比較のベンチマークではありません。

**画面を離れる前、またはウインドウを閉じる前に書き出してください。**
下書きと原本の作業コピーはセッション内だけに保持します。画面の終了時はモデルと作業コピーを解放し、次の利用者には新しいセッションを用意します。

## 対象と判断の境界

- 1ファイルを1レシートとして扱います。JPEG・PNG・HEIC/HEIF・単一画像の TIFF・1〜5ページのロックされていない PDF が対象です。
- 最大20ファイル、1ファイル20 MiBです。同じ内容の二重追加、上限超過、読めないページを黙って無視しません。
- 整数の日本円が対象です。曖昧な金額・日付や OCR の警告は確認が必要です。外貨換算や明細ごとの按分は行いません。
- JEV は8費目の候補だけを返します。金額・日付・保存先を作らせません。表示言語を変えても、入力やモデルの質問は変えません。
- 最大分類確率0.75未満は要確認にします。この暫定閾値や表示スコアを、実レシートで測った正解率と見なさないでください。
- 同梱の4画像は合成サンプルと明記しています。消耗品・飲食・交通費・私用を含む混在購入の例で、一般的な日本語レシートの精度評価ではありません。
- 事業での用途や税務上の扱いは、レシートだけでは確定できません。複式簿記、銀行・会計サービスへの登録、iPhone版は含みません。

## 保存と停止

読み込んだ原本の bytes と SHA-256 を保持し、その後に元ファイルが変わっても、別の内容へ黙って置き換えません。
元ファイルは移動・削除しません。書き出しは確認済みの台帳に対応するコピーだけを新規フォルダへ保存します。

保存中の差し替え・内容改変・余分なファイルを検査し、既存の保存先を上書きしません。
公開前の通常の失敗・取消では途中フォルダを片付けます。無関係な内容へ差し替わっていた場合は削除せず、片付けられない旨を表示します。
CSV の文字列セルは引用・式の先頭を保護し、JSON の金額は厳密な十進文字列で保存します。

## 検証

純状態・実行部の試験は、古い完了の拒否、編集による確認解除、取消・解放待ち、保存先選択の取消、停止と完了の競合、所有者交代を扱います。
モデルを使う試験は通常実行ではスキップし、`AGENTS.md` の共有 heavy-job ロック下で明示実行します。
[固定した機能確認計画](validation/receipt-desk/plan-20261106.json)は、モデル版と4画像、期待する分類・金額・確認操作を定めています。

main 上で本人のレシートを使う確認と、停止・画面離脱・複数ウインドウの本人受入は [#508](https://github.com/oka-yuji/coreai-samples/issues/508) で追跡します。
実行部の限定的な結果、コードの契約、コマンドの詳細は [English guide](receipt-desk.md) を参照してください。
